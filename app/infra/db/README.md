# Database Schema (SAFECHOICE Backend)

이 디렉토리는 SAFECHOICE 백엔드에서 사용하는 **DB 스키마의 계약서** 역할을 한다.

⚠️ 현재 단계에서는

- 실제 DB 연결 ❌
- 마이그레이션 실행 ❌
- ORM 연동 ❌

오직 **구조 합의 및 기록용**이다.

---

## 목적

- 백엔드, 프론트엔드, 데이터 전처리 담당 간
  **공통 데이터 구조 기준**을 맞추기 위함
- MVP 개발 중 스키마 변경 이력을 관리하기 위함
- 추후 Supabase / PostgreSQL 연동 시 기준점으로 사용

---

## 사용 원칙

- `schema.sql`은 **실행 스크립트가 아님**
- 설계 변경 시:
  1. SQL 수정
  2. 변경 이유를 커밋 메시지에 명시
- 임의로 컬럼 추가 금지  
  (도메인 합의 없이 늘리면 분석 로직 깨짐)

---

## 테이블 개요

### 1. scenarios

- 시뮬레이션 시나리오 저장
- step 구조는 JSONB로 통째 저장
- 시나리오 생성 방식은 본 시스템의 관심사가 아님

### 2. sessions

- 사용자 시뮬레이션 실행 단위
- 현재 진행 중인 step 포인터 보유

### 3. events

- 사용자 행동 로그
- 모든 분석은 이 테이블을 기반으로 수행됨

---

## 향후 계획 (아직 안 함)

- SQLAlchemy 또는 Prisma 연동
- 마이그레이션 도구 도입
- 인덱스 / 성능 튜닝

지금은 **하지 않는다**.  
MVP에 필요 없다.

---

## 요약

- 이 디렉토리는 코드가 아니라 **약속**
- 실행보다 **설명 가능성**이 우선
- 변경은 신중하게, 기록은 명확하게
